Pareto Efficiency Curve: Accuracy vs. CPU Latency

The optimal architecture maximizes MTEB Accuracy while minimizing CPU Latency per schema field.

1. The Baseline Knee

MiniLM is fast (180ms) but only achieves 56.26 MTEB with high concept collision in 384 dimensions.

2. The BGE-Base Optimum

Jumps to 63.55 (+7.3% accuracy) while maintaining sub-second latency (0.42s) on commodity CPU.

3. The Diminishing Plateau

BGE-Large and 7B LLMs provide only +0.5% to +4% accuracy but cost 400% to 3000% more execution time.

1. BERTMap (BERT-base) Rejected

Published by Oxford University for comparing static OWL files. It uses an older 2018 BERT architecture without contrastive pre-training. Cannot connect to live databases, has no multi-agent verification, and achieves only 52.80 MTEB.

2. all-MiniLM-L6-v2 Replaced Baseline

Ultra-light (80MB) and very fast (180ms), but limited to 384 dimensions. Closely related physical properties (EC, TDS, Salinity) cluster too closely together, leading to ambiguity in complex schemas.

3. all-mpnet-base-v2 Viable Runner-Up

Solid 768-dim model from 2021. However, BGE-Base scores +2.05 points higher on MTEB (63.55 vs 61.50) due to RetroMAE pre-training and asymmetric query tuning.

4. BAAI/bge-large-en-v1.5 GPU Ideal

1024 dimensions with 64.11 MTEB. Excellent on GPU (~18ms), but suffers from law of diminishing returns on CPU (2.8 seconds latency for only +0.56% accuracy gain).

5. allenai/scibert_uncased Architecturally Flawed

Trained strictly as a Masked Language Model on PubMed papers. Lacks contrastive sentence pooling weights, resulting in representation anisotropy where all cosine similarities cluster around 0.88–0.89 with no separation.

6. 7B LLM Embedders (Qwen2 / NV-Embed) Hardware Incompatible

Ranked #1 on MTEB (67.56) with 3584 dimensions, but requires 16GB dedicated GPU VRAM. Takes 22+ seconds per field on CPU, causing ingestion timeouts.
